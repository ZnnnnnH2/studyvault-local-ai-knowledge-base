## 测试命令与结果

在项目根目录执行：

```powershell
uv run --group dev python -m unittest discover -s tests -v
uv run --group dev python tests/browser_check.py --capture-report
node --check static/app.js
git diff --check
```

- **后端：34/34 通过**，包括原有 4 项测试、6 项恢复测试、6 项基础 API 测试、8 项附加功能测试和 10 项可用性测试。无效快照测试还包含缺文件、坏 JSON、重复会话、重复标注、缺失/未知标注、错误消息计数、非法字段等 10 种情况。
- **真实浏览器：通过**。使用 Microsoft Edge headless，JavaScript 页面错误为 0；覆盖分页、搜索筛选、迟到响应、失败重试、批注、建卡、答对/答错、刷新持久化、JSON/Markdown 下载和快照哈希。
- **恢复完整性：通过**。空库对合成演示快照恢复会话 14、消息 56、会话标注 14、标签关联 19、知识点关联 14；SQLite 完整性为 `ok`，外键违规为 0。真实 754 语料按 DATA_POLICY.md 只在本机验证、不随仓库公开。
- **重复恢复：通过**。新增会话/消息/摘要/标注/关系为 0，既有用户内容保留；每次成功恢复会增加一条审计记录。
- **原始数据：保持不变**。业务截图使用临时数据库，演示新增的批注与复习卡不写入日常工作区数据库；两份历史 JSONL 未修改。

测试使用受控文件及临时 SQLite 库，没有扫描当前用户的 Agent 目录。工作区的 `studyvault.db` 则由标准恢复命令单独生成，属于被 Git 忽略的本地运行数据。

## 数据与演示范围

恢复并不等同于复制原机器数据库：快照没有课程字段，因此按现有规则重建课程；旧标签和深读标注不代表本轮重新人工确认。报表中的课程分布与知识点合并口径已明确写入项目报告。

当前库 JSON 和课程 Markdown 是问答资料导出，历史 JSONL 是固定归档；它们不包含全部运行状态，不能当作完整 SQLite 备份。固定用户、粗粒度课程识别、本机会话不增量同步等限制仍在 README 与报告中如实列出。
